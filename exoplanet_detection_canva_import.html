Problem and aims

The problem

NASA's Kepler mission produced far more candidate signals than can be vetted by hand, and most turn out to be false positives — eclipsing binaries, instrumental artefacts, background stars.

This project

Compare three machine learning models on the same data, the same preprocessing and the same evaluation, so that differences in performance come from the model rather than the setup.

Logistic Regression · Random Forest · Multi-Layer Perceptron
Dataset: 9,564 Kepler Objects of Interest — 4,839 false positives, 2,747 confirmed, 1,978 candidates

Method: what protects the result

Preventing data leakage

14 columns removed — vetting flags, disposition scores, confirmed planet names — each recorded with the reason. A keyword sweep caught 5 the manual list missed.

Splitting by host star

One star can host several KOIs. Splitting on kepid keeps all observations of a star on one side, so the model cannot recognise the star instead of the transit.

Feature selection on training data only

118 → 99 → 70 → 69 features. Missingness and correlation filters computed on the training set alone.

Limitations and conclusion

Limitations

  • CANDIDATE objects are grouped with CONFIRMED, so the model learns triage — "worth following up" — rather than confirmed planethood. Candidate labels are not independently verified.
  • The most influential features are centroid-offset diagnostics, closely related to the vetting process itself.
  • The MLP is a neural baseline on tabular features, not light-curve deep learning as in AstroNet or ExoMiner.

Conclusion

All essential CA1 requirements met, plus the web interface from the desirable list. Random Forest performed best (F1 0.895, ROC-AUC 0.967) under a consistent, reproducible experimental framework.
